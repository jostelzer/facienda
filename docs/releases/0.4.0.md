# Facienda 0.4.0

- Folders and sources now belong to the workspace rather than each group. The Memory page opens with Places: where tasks work, what they read, and sources agents propose.
- One workspace can read another's memory. Set the link from a planet's menu or by Option-dragging a memory onto the workspace that should read it.
- The open planet keeps its size and glows in its own colour. Planets stay where they are when a workspace opens.
- The bar's Incoming shows only what is live. A Codex link with words continues that chat, and a missing earlier task offers its chat instead.
- A chat belongs to one task in any workspace. Facienda now says which task has it and where, with a way to open it.
- Agents spend far fewer tokens. Task chats are bounded at 250k tokens of context instead of growing for days, memory answers leave out embeddings, and an idle Claude runner wakes in about two steps instead of five. Fast now applies to the next task only.
- Facienda refuses new work while Codex or Claude can't take it. The Claude runner wakes again after a refused turn, and waiting checks keep their cadence quietly.
- Memory learns only from what you typed in Codex, not from the browser and attachment context Codex adds.
- Dictation waits for the speech model's first setup on a Mac instead of losing words. Long Codex chats are read in pages so they can be indexed.
- Return on a new group's name makes the group. Facienda's Claude sessions are filed into one sidebar group, and its Codex chats into their project.

The Mac app requires macOS 26 or later. Existing workspaces are migrated when opened; keep your normal library backups.
